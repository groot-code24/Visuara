# V8 benchmark protocol and results

## Protocol
- **Footage provenance:** 100% procedurally generated by `benchmark/fixtures.py` and `benchmark/fixtures3d.py` (original textures, no third-party content). **No real footage.** Gate C and real-world claims stay open.
- **Ground truth:** 2D scenes use known world→image homographies, with a ground-truth composite (product inserted in the world plane *before* camera, lighting and colour changes). 3D scenes use a true pinhole camera (f = 520 px at 640×360) and true per-frame pose, with a ground-truth render using the true camera.
- **Labels:** suitable or unsuitable plus expected reason code, assigned by construction **before** evaluation.
- **Splits:** dev = seeds 0–1 (threshold and design choices only); **test = seeds 2–4, held out**, run once on the frozen code. Reproduce with the commands in each section.
- **What this cannot show:** human-perceived realism, behaviour on real cameras, materials, lighting or compression. Small held-out samples give wide uncertainty.

## A. Placement gate (V6 policy, frozen) after the V8 tracker change
`python -m benchmark.run_benchmark --split all`: 14 kinds × 5 seeds = 70 clips.

| Split | Correct decisions | False accept | False reject | Expected code | Corner error (accepted) mean / max | Outputs validated | Median analysis |
|---|---|---|---|---|---|---|---|
| dev | 28/28 | 0/14 | 0/14 | 12/14 | 0.40 / 3.46 px | 14/14 | 3.7 s |
| **test** | **42/42** | **0/21** | **0/21** | 18/21 | 0.39 / 3.40 px | 21/21 | 4.8 s |

Compared with V6 (test): same decisions. Max corner error 2.94 → 3.40 px (mean unchanged). Analysis 0.44 → 4.8 s (ECC re-anchoring). The re-anchoring is what makes large-viewpoint 3D scenes trackable (orbit: 5.7 px drift → 0.82 px).

## B. 2D compositing quality (V6 compositor vs V8, same geometry)
`python -m benchmark.run_2d_quality --seeds 2 3 4`: 7 kinds × 3 held-out seeds = 21 clips; product is a cut-out with transparent edges. Metric: mean CIE76 ΔE vs ground truth inside the product region (lower is better).

| Kind | V6 | V8 alpha/linear only | **V8 full** |
|---|---|---|---|
| static | 3.60 | 3.35 | 3.35 |
| pan_zoom | 4.20 | 3.94 | 3.94 |
| perspective | 6.38 | 6.12 | 6.12 |
| handheld | 4.54 | 4.34 | 4.34 |
| mild_lighting | 5.78 | 5.52 | 5.14 |
| exposure_drift | 7.81 | 7.77 | **4.90** |
| wb_drift | 6.18 | 5.93 | 5.27 |
| **all** | **5.50** | 5.28 | **4.72 (−14%)** |

V8 was worse than V6 on **0/21** clips. The edge-band ΔE did not change (3.14 vs 3.14): on this asset, edge error is dominated by sub-pixel geometry. The premultiplied fix is shown separately by a unit test (V6 darkens a white-on-white edge to 224; V8 ≥ 250). One dev-only adjustment: a ±2% deadband on colour gains, added after dev seeds showed +0.05 ΔE noise on clips without lighting change.

## C. 3D placement (TRACKED_3D)
`python -m benchmark.run_3d_benchmark --seeds 2 3 4`: 8 kinds × 3 held-out seeds = 24 clips; textured 256-triangle bottle GLB.

| Metric (held-out) | Result |
|---|---|
| Correct decisions | 23/24 |
| False accept | **0/12** |
| False reject | **1/12** (dolly s2, see below) |
| Expected rejection code present | 10/12 (2 occluder clips rejected via occlusion/drift codes instead of the foreground code) |
| Focal error, estimated cases | ≤ 1.04% |
| Rotation error vs true camera | ≤ 0.86° (≤ 0.17° when focal is estimated; 0.77–0.86° on top-down with supplied FOV) |
| Translation error | ≤ 0.9% of camera distance |
| Product anchor error | mean 0.11 px, max 0.66 px |
| Silhouette IoU vs true-camera render | ≥ 0.90 (≥ 0.98 for orbit, dolly and handheld) |
| Rendered outputs passing validation | 11/11 |
| ΔE vs ground-truth render (object + shadow region) | mean 4.2 (encoding plus geometry residual) |
| Median analysis / render time per clip (61 frames, 640×360, CPU) | 10.7 s / 6.6 s |

Dev split (seeds 0–1) before freezing: 16/16 correct after two design fixes made on dev data only. The first was ECC re-anchoring (orbit was falsely rejected for drift). The second replaced the focal-confidence test, because the top-down shot was **falsely accepted** with a 20% focal error.

**Held-out false rejection (dolly s2).** The object's region extends above the table's far edge into background that does not move with the plane. The full-frame-homography foreground check measured 0.035 moving fraction against a 0.03 threshold. In real footage the same mechanism (parallax behind the object) will cause more rejections. The threshold was **not** changed after seeing held-out data. Fixing this needs depth- or segmentation-aware motion analysis.

> **Correction (V9).** A V9 diagnosis showed this explanation was wrong. These fixtures contain a single plane, so there is no parallax. The flagged pixels were thin, high-contrast texture lines in the far, heavily minified part of the plane, which flicker from frame to frame because of aliasing in the synthetic renderer. See [docs/v9/3d-scene-check.md](../v9/3d-scene-check.md), which also adds fixtures with real depth (a back wall and a static occluder).
