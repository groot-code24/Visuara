# Defect register

One row per defect. **Severity:** P0 critical security or data integrity; P1 production-blocking or high; P2 broken or incomplete core function; P3 performance, usability or maintainability; P4 enhancement. **Status** uses the release vocabulary: `NOT_STARTED`, `IN_PROGRESS`, `IMPLEMENTED`, `TESTED`, `CI_VERIFIED`, `EXTERNALLY_VERIFIED`, `PRODUCTION_VERIFIED`, `BLOCKED`. Nothing here is `CI_VERIFIED` yet, because CI runs only when the owner pushes.

Each defect's reproduction is the procedure that failed before its fix; the verification requirement is what must pass afterwards.
